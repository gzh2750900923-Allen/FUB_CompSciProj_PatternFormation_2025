# Grey-Scott Model Discretization Schemes and Performance Benchmarking

This module covers the implementation of the second-order finite difference method on a Cartesian grid, including a comparative analysis between the Explicit Euler method and the Crank-Nicolson scheme. Please refer to and execute the relevant program files in the following logical order:

## 1. Core Operator Interface and Automated Verification

* **File Name**: `UnitTest_discrete_laplacian_2d.py`
* **Corresponding Task**: Define a general interface and implement unit tests.
* **Technical Definition**: Implements the second-order central difference approximation of the 2D Laplacian operator, integrating periodic boundary conditions. As the underlying dependency, this file verifies the mathematical accuracy of the spatial discretization through constant field and pulse field test scripts.

## 2. Explicit Time-Stepping Engine (Explicit Solver)

* **File Name**: `explicit_solver.py`
* **Corresponding Task**: Implement the explicit discretization scheme.
* **Technical Definition**: A time integrator based on the Explicit Euler method. This algorithm relies entirely on the local state at the current time step for state evolution, with a single-step computational complexity of O(N^2). Constrained by the CFL stability condition, its time step (Delta t) has a strict upper limit.

* **File Name**: `main_gs_visualization.py`
* **Corresponding Task**: Visual output of the Grey-Scott model.
* **Technical Definition**: Invokes the explicit solver and integrates the parameters for giraffe/leopard fur textures. This script is responsible for managing the simulation loop, parameter updates, and real-time rendering of pattern generation via Matplotlib.

## 3. Implicit Time-Stepping Engine (Implicit Solver)

* **File Name**: `implicit_CN_solver.py`
* **Corresponding Task**: Implement the Crank-Nicolson finite difference approximation.
* **Technical Definition**: Employs a semi-implicit (IMEX) discretization scheme. The Crank-Nicolson format is applied to the diffusion term, utilizing `scipy.sparse.linalg.cg` to implement a Matrix-Free conjugate gradient iterative solution for the linear system of equations. This method is mathematically second-order accurate in time and unconditionally stable.

* **File Name**: `main_CN_visualization.py`
* **Corresponding Task**: Independent functional verification and visualization of the implicit solver.
* **Technical Definition**: A dedicated execution script for the Crank-Nicolson solver. It demonstrates the IMEX format's ability to model complex morphologies while verifying the convergence and pattern formation quality of the implicit scheme under long-period simulations.

## 4. Performance Benchmarking and Convergence Analysis

* **File Name**: `main_benchmark.py`
* **Corresponding Task**: Validate the order of the algorithm and conduct performance benchmarking.
* **Technical Definition**: The core performance evaluation script. Under unified initial conditions, spatio-temporal step sizes, and model parameters, it quantitatively compares the wall-clock time and numerical stability of the explicit and implicit algorithms. The side-by-side comparison images generated by this script aim to reveal the trade-off between computational overhead and the smoothing effect caused by numerical damping in the implicit scheme, providing data support for the project's performance report.
